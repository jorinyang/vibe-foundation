# SPEC-AUTH-02 处方

## 动作

1. 在读取接口里做**两级判断**，且顺序不能反：
   - 先判身份是否有效 → 无效返回 `401`
   - 再判**资源归属** → 不属于当前用户返回 `403` 或 `404`
2. 越权分支里**只返回错误码和固定文案**，不要把查询结果放进响应体
3. 归属判断用的条件是"资源 owner == 当前登录主体"，不是"资源 id 在请求参数里"
4. 若用 ORM，把归属条件写进 `where`（`where: { id, ownerId: currentUser.id }`），查不到就是 404——**用查询条件做鉴权，比查到再判断更不容易漏**
5. 重跑验证命令

## 判定通过条件

```bash
node bin/vibe-check.mjs SPEC-AUTH-02 --project .
```

退出码 `0`。

## 不可自动修复时

- 若项目当前没有可用的两个测试用户/两条测试资源，先在 `.vibe/config.json` 的 `authzProbe` 里补齐；**不要为了让判定过而把 `denyStatus` 改成包含 200**。
- 若该接口设计上就是公开的，它不该出现在 `authzProbe` 里——换一个真正需要归属校验的接口。
