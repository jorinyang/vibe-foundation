# SPEC-AUTH-02 负向用例

## 前提

同一份 `authzProbe`，把 `service.startCommand` 指向不同行为的夹具。

## 动作与期望

1. 夹具**不做归属校验**（任何合法 token 都能读任何资源）
   → 子判定「A 读 B 的资源 → 拒绝」`FAIL`（实际 200），退出码 `1`

2. 夹具**返回 403 但把 B 的资源对象一起放在响应体里**
   → 子判定「越权响应不含他人资源标识」`FAIL`，退出码 `1`

3. 夹具对未带 token 的请求也返回数据
   → 子判定「A 读自己的资源」仍可能 PASS，但跨用户必然 FAIL；本条用于确认 probe 没有把"没鉴权"误判成"鉴权正常"

## 失败含义

第 2 条是这条判定存在的核心理由：**「403 但数据泄露」在监控里看起来是安全的**。只看状态码的测试永远发现不了它。
